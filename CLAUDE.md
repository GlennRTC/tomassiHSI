# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

Two static HTML pages, no package manager and no client-side JS framework: [index.html](index.html), the Spanish-language marketing landing page for Tomassi HSI (a clinical systems integration consultancy — HL7v2/FHIR/ASTM lab interoperability work in LATAM), and [docs.html](docs.html), a standalone "Documentos" page reachable only via the nav's "Docs" link. Most of both pages is hand-authored, but the Casos cards/modals on index.html and the Documentos list on docs.html are generated from JSON data — see "Content data layer" below before editing either. Styling comes from Tailwind CSS loaded via a CDN `<script>` tag, configured inline through a `tailwind.config` script block in each page's `<head>` — kept identical across both files. Fonts (JetBrains Mono) and icons (Material Symbols Outlined) load from Google Fonts. There is no custom JavaScript — all interaction is pure CSS: `:hover`/`:focus-within` for nav, card, and methodology-tooltip states; `:target` drives both the mobile nav panel (`#mobile-menu`, opened via the header hamburger link and auto-closed by navigating to any other anchor) and the Casos case-study modals (`#modal-prj-00N`, with an `html:has(.case-modal:target)` scroll-lock rule, on index.html only).

### Content data layer

`data/casos.json` and `data/documents.json` hold the editable Casos and Documentos content; `documents/` holds the actual PDF/MD files that `documents.json` entries reference by filename. `build-content.js` (plain Node, no dependencies, no `package.json`) reads that JSON and regenerates three marker-delimited regions: `<!-- CASOS_CARDS:START/END -->` and `<!-- CASOS_MODALS:START/END -->` in `index.html`, and `<!-- DOCUMENTS:START/END -->` in `docs.html`. After editing the JSON (or adding/removing a file under `documents/`), run `node build-content.js` to regenerate those regions. Never hand-edit HTML directly inside the marker comments — the next script run silently overwrites it.

Both pages share the same header/nav/footer chrome, hand-copied (no templating). On `docs.html`, anchor links that target landing-page sections are qualified as `index.html#hero`, `index.html#projects`, etc., since those ids don't exist on `docs.html` itself — keep that qualification if the chrome is edited on one page and mirrored to the other.

This file originated as a Google Stitch prototype (`stitch_tomassi_hsi_systems_integration/DESIGN.md`, `screen.png` — the prototype's own `code.html` was moved here and became this file) implementing the "Carbon Light" direction from `docs/superpowers/specs/2026-08-08-landing-redesign-design.md` §10, superseding the earlier hand-rolled "Editorial Minimal" system.

## Working with this file

- Open directly in a browser to preview (`xdg-open tomassi-hsi-mockup.html` or similar) — no server or build step needed (Tailwind compiles client-side via the CDN script).
- Keep content in Spanish (the site's language, per `lang="es"`), matching the existing tone: technical, terse, industry-specific (HL7, FHIR, ASTM, LIS/HIS terminology).
- Styling is "Carbon Light": one accent color (`primary-container` = `#FF6B00`), one typeface (JetBrains Mono, the `font-sans` key in `tailwind.config`), `0px` border-radius everywhere (never add a `rounded-none` utility — nothing here has a default radius to override), 1px solid borders instead of shadows for hierarchy. Extend `tailwind.config`'s `theme.extend` rather than hardcoding new colors or adding a second font.
- Sections are anchor-linked from the nav: `#hero`, `#projects` (Casos), `#interoperability` (Servicios), `#process` (Metodología), `#solutions` (Soluciones Desarrolladas), `#about` (Acerca), with `#contact` nested inside `#about`'s contact card — keep `id` attributes in sync with the nav/footer `href`s if restructuring sections. `Docs` in the nav is not an anchor — it's a real page link to `docs.html`.
- `#solutions` (Soluciones Desarrolladas) showcases Glenn's own built products/tools, distinct from `#projects` (Casos, client integration work). Unlike Casos cards (which open an in-page modal via `:target`), each Soluciones card is a whole-card `<a target="_blank" rel="noopener">` linking straight out to that solution's own existing site/npm page — there's no local write-up to keep in sync, so don't add one without checking the destination is still accurate first.
- Placeholder contact links (`href="#"`) for phone/email/LinkedIn, and the placeholder project images in the Casos cards (`googleusercontent.com` stock URLs), are intentional mockup stand-ins — not broken links/assets to "fix". Casos project copy (titles, descriptions, tags, countries, periods) now lives in `data/casos.json`, not directly in index.html (see "Content data layer" above) — it must stay real and verified (sourced from Glenn's actual project repos) — never replace it with invented technical claims.
